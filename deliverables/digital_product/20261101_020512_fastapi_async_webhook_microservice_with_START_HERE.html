import hmac
import hashlib
from fastapi import Header, HTTPException, status, Request

async def verify_webhook_signature(
    request: Request,
    x_signature: str = Header(..., description="HMAC SHA256 signature from provider")
) -> bytes:
    """
    Validates incoming webhook payloads against a shared secret using constant-time comparison
    to prevent timing attacks.
    """
    body = await request.body()
    
    # Compute expected signature
    computed_signature = hmac.new(
        key=request.app.state.settings.WEBHOOK_SECRET_KEY.encode("utf-8"),
        msg=body,
        digestmod=hashlib.sha256
    ).hexdigest()
    
    # Secure constant-time comparison
    if not hmac.compare_digest(f"sha256={computed_signature}", x_signature):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid signature cryptographic proof."
        )
    return body

4. Common Anti-Patterns & Gotchas to Avoid

1. Synchronous Processing inside Webhook Route

Anti-Pattern:* Performing database writes, third-party API calls, or intensive computing directly inside the FastAPI route function. Consequence:* Sender webhooks timeout (usually after 5-10 seconds), causing cascading retries and potential duplication loops. Solution:* Always offload heavy tasks to Celery/Redis immediately and return an HTTP 202 Accepted within 50 milliseconds.

2. Skipping Cryptographic Payload Verification

Anti-Pattern:* Trusting incoming HTTP requests blindly without evaluating the X-Signature header. Consequence:* Vulnerable to spoofing attacks where malicious actors flood your database with fake events. Solution:* Always wrap signature verification as a FastAPI dependency (Depends()) before the payload body is processed.

3. Non-Idempotent Worker Architecture

Anti-Pattern:* Writing database operations that increment balances or create records without checking if the event_id has already been processed. Consequence:* Network failures or worker restarts cause duplicate webhooks to execute twice. Solution:* Maintain an processed events ledger in Redis or PostgreSQL keyed by event_id with a time-to-live (TTL) expiration.

4. Running Containers as Root

Anti-Pattern:* Using default container setups that execute Python processes as the root superuser. Consequence:* Container breakout vulnerabilities expose the underlying host kernel. Solution:* Implement non-root system users (appuser) inside production Dockerfiles.

5. Performance & Optimization Tips

Uvicorn Worker Scaling: Match your Uvicorn worker count to your CPU cores using the formula (2 $CPU_CORES) + 1, or deploy behind an Nginx reverse proxy load balancer.
  • Celery Acks Late: Keep task_acks_late=True configured in Celery. This guarantees that if a worker pod crashes mid-execution (e.g., out-of-memory error), the task returns to the Redis queue instead of being permanently dropped.
  • Connection Pooling: When attaching databases (PostgreSQL/MongoDB) in production, initialize connection pools at application startup (lifespan context manager) rather than opening a fresh connection per task invocation.
  • Payload Compression: If processing large payloads (>500KB), configure Redis with compression middleware or store payloads in Object Storage (S3/MinIO) passing only reference pointers through the queue.
