## 3. Production Code Patterns & Architecture Examples

### A. The Resilient Execution Wrapper (Node.js/TypeScript)
*Designed to wrap unstable API calls with retry logic and telemetry.*

```typescript
import { retry } from '@genie/utils';

async function executeGeniePrompt(payload: PromptSchema) {
  return await retry(async () => {
    const response = await fetch('https://api.genie.ai/v4/chat', {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${process.env.GENIE_KEY}` },
      body: JSON.stringify(payload)
    });

    if (!response.ok) {
      throw new Error(`GenieStatus:${response.status} - Check API quota.`);
    }

    return response.json();
  }, { retries: 3, factor: 2 });
}
```

## 4. Common Anti-Patterns & Gotchas to Avoid

1. **The "Infinite Context" Trap:** Pushing your entire chat history into every request. 
   * *Fix:* Implement a sliding window buffer that summarizes older messages into a "system state" block.
2. **Hardcoded API Keys:** Never commit keys to source control.
   * *Fix:* Use a `config.toml` approach with environment variable injection.
3. **Blocking Synchronous Calls:** Running LLM requests in the main event loop will lock your UI/API.
   * *Fix:* Always wrap LLM execution in `async/await` and offload to a worker thread for high-load environments.
4. **Ignoring `max_tokens`:** Allowing the model to output indefinitely leads to runaway costs.
   * *Fix:* Always explicitly set `max_tokens` based on expected response length.

## 5. Performance & Optimization Tips

*   **Prompt Compression:** Use "Few-Shot" examples sparingly. They consume high token counts. If you use >3 examples, consider **Fine-Tuning** instead.
*   **Latency Budgeting:** Set a `timeout` header on your fetch requests. A response taking 10 seconds is usually a failure for the end-user.
*   **Caching Strategy:** Hash your inputs. If a user asks the exact same question twice, serve the cached JSON result from Redis rather than billing the API.
*   **Request Batching:** If you need to process multiple items, ensure you are using the batch API endpoints to reduce overhead.
