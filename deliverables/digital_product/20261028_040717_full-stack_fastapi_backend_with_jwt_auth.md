## 3. Production Code Patterns & Architecture Examples

### A. Async JWT Security Middleware
*Located in `app/core/security.py`*

```python
from datetime import datetime, timedelta
from jose import jwt
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
SECRET_KEY = "SUPER_SECRET_CHANGE_THIS"
ALGORITHM = "HS256"

def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=30)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
```

### B. Production Dockerfile (Multi-Stage)
*Located in root/Dockerfile*

```dockerfile
# Stage 1: Build
FROM python:3.11-slim as builder
RUN pip install poetry
COPY pyproject.toml .
RUN poetry export -f requirements.txt > requirements.txt

# Stage 2: Runtime
FROM python:3.11-slim
WORKDIR /app
COPY --from=builder requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## 4. Common Anti-Patterns & Gotchas to Avoid

*   **Hardcoding Secrets:** Never put keys in your code. Use `.env` files and `pydantic-settings` to load environment variables.
*   **Blocking Calls in Async Paths:** Using `requests` or standard blocking file I/O inside `async def` routes will kill your event loop performance. Use `httpx` or `aiofiles`.
*   **"Fat" Models:** Keep your Pydantic schemas separate from SQLAlchemy ORM models. Never pass ORM models directly to the response schema.
*   **Not Setting CORS:** Leaving `allow_origins=["*"]` in production is a critical security vulnerability.

## 5. Performance & Optimization Tips

1.  **Gunicorn Workers:** Always run your app behind `gunicorn` with `uvicorn.workers.UvicornWorker` to utilize all CPU cores.
    *   *Cmd:* `gunicorn -w 4 -k uvicorn.workers.UvicornWorker app.main:app`
2.  **Connection Pooling:** Always configure your SQLAlchemy engine with `pool_size` and `max_overflow` to prevent database connection exhaustion under load.
3.  **Caching:** Integrate `aioredis` for caching heavy query results to avoid redundant hits to the PostgreSQL database.
4.  **Schema Validation:** Use `pydantic` v2, which is significantly faster due to the Rust core implementation.
